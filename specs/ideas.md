# Ideas

<!-- Uncommitted possibilities; promote to roadmap.md when decided. -->

- **More supply-chain checks in CI.** `cargo audit` is in place (`deps-audit.yml`: weekly + on manifest changes). Still open: `cargo deny` for licenses, banned and duplicate crates; a dependency-count budget that fails CI when the runtime tree grows past an agreed number, so growth is always a deliberate decision.
- **Release binaries.** The release workflow publishes to crates.io and creates a GitHub release; attaching prebuilt macOS/Linux binaries to the release would allow install without a Rust toolchain.
- **LLM e2e tests.** A harness in `e2e/` (outside the crate; specdev itself never calls an LLM) drives a real agent through scripted user turns in a throwaway git repo, then asserts on specdev's deterministic state: status, log lines, `check`, no commits. First adapter: `opencode run -m zai/glm-4.7-flash --auto -s <session> --format json`, key in `ZHIPU_API_KEY`, `opencode.json` denying git commit/push/checkout/branch; use the CLI, not the opencode GitHub action (built for comment-driven repo changes). opencode reads `.agents/skills/`, so `skill install --local` works as is; an adapter script keeps it agent-agnostic. Scenarios: small task (plan → implement → "looks good" → done), revision, partial praise. CI: `workflow_dispatch` + weekly, not a required check (cost, secrets, nondeterminism). Start with a local spike, run 3 times, to measure reliability.
